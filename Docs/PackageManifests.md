# Shared package manifests

Each runtime package owns one `resources/<package>_memoria.json` source, emitted as a `<package>_memoria.txt` NWN resource. The single supported manifest schema is version 1. It includes the build-generated package `name`, `version`, and `dependencies` fields together with the source `schema`, `id`, and optional subsystem sections. Every `NwnRequiredPackage` supplies a dependency `ModId` and NuGet-style `Versions`. Endpoints may contain one to three numeric components, and `;` joins alternative intervals. The range must have a bounded, inclusive minimum equal to the referenced project's current `Version`. Dependency sources are compiled into consumers, so any dependency bump requires updating and rebuilding every consumer with its latest fixes. The build rejects invalid ranges, mismatched minimums, and ranges that do not contain the current version. Immutable [API snapshots](ApiSnapshots.md) continue to be published for possible future use.

The shared [memoria_loader.nss](../Mods/Memoria/source/memoria_loader.nss) enumerates TXT resources from the `OVERRIDE:` key table once per loaded runtime and retains resrefs ending in `_memoria`. It rejects malformed or duplicate identities and recursively disables packages with missing, incompatible, or disabled dependencies. Both [memoria_boot.nss](../Mods/Memoria/source/memoria_boot.nss) and [meconfig.nss](../Mods/ConfigurationManager/source/meconfig.nss) consume that filtered list, so a disabled mod receives neither heartbeat dispatches nor configuration actions.
