# Shared package manifests

Each runtime package owns one `resources/<package>_memoria.json` source, emitted as a `<package>_memoria.txt` NWN resource. Schema 2 includes the build-generated package `name`, `version`, and `dependencies` fields together with the source `schema`, `id`, and optional subsystem sections. Every `NwnRequiredPackage` supplies a dependency `ModId` and NuGet-style `Versions`. Inclusive `[]` and exclusive `()` bounds are supported, endpoints may contain one to three numeric components, and `;` joins alternative intervals: `[1.0,3.5];[3.7,4.0)`. The build rejects invalid ranges and ranges that do not contain the referenced project's current `Version`.

The shared [memoria_loader.nss](../Mods/Memoria/source/memoria_loader.nss) enumerates TXT resources from the `OVERRIDE:` key table once per loaded runtime and retains resrefs ending in `_memoria`. It rejects malformed or duplicate identities and recursively disables packages with missing, incompatible, or disabled dependencies. Both [memoria_boot.nss](../Mods/Memoria/source/memoria_boot.nss) and [meconfig.nss](../Mods/ConfigurationManager/source/meconfig.nss) consume that filtered list, so a disabled mod receives neither heartbeat dispatches nor configuration actions.
