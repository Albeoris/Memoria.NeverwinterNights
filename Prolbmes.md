## Отчёт: потенциальные точки конфликта между модами разных авторов

Ничего не исправлял, только нашёл и задокументировал. Разбито по серьёзности.

### 1. ESI-ключи инъекций — «числа-как-бы-строки» без реестра уникальности (самое серьёзное)

`ESI_InjectToObject(oObject, sKey, nHandler, sScript, nPlacement)` в `esi_lib.nss:159-172` хранит инжектированный скрипт в JSON-карте `jScripts`, ключ — это `sKey` **как есть**: `JsonObjectSet(jScripts, sKey, JsonString(sScript))`. Если два разных мода передадут одинаковый `sKey` для одного и того же `(nHandler, nPlacement)`, второй **молча перезапишет** обработчик первого — без ошибки, без предупреждения.

Ключи сейчас выбираются авторами вручную как голые числа, а не как неймспейс-строки:
- `melse_lib.nss:106-111` — `MELSE_INJECT_KEY_* = "100"`, `"200"`, `"300"`, `"400"`, `"410"`, `"500"` — короткие круглые числа, максимально велика вероятность, что другой автор (или даже будущий мод в этом же репозитории) выберет то же самое.
- `mecalm_lib.nss:10` — `MECALM_ESI_INJECTION_KEY = "9317"`.
- `metact_core.nss:9` — `METACT_ESI_KEY = "7421"`.
- `memoria_config.nss:399` — литерал `"config"`, ещё более вероятное совпадение с чужим мод (весьма «обычное» слово).
- Даже собственный README ESI показывает пример `"acme_evt"` — то есть правильный паттерн (неймспейс-строка) существует, но CALM/TACT/LSE/Config ему не следуют.

Дополнительно: если `sKey` числовой (`^[0-9]+$`), значение параллельно кладётся в «псевдо-массив» через `RAV_SetLocalArrayString(oObject, ..., StringToInt(sKey), sScript)` (`esi_lib.nss:172`) — то есть число буквально используется как индекс массива, а не просто как имя.

### 2. Полная перезапись базовых скриптов движка (плоское пространство имён override)

LSE полностью подменяет собой файлы `nw_c2_default1.nss`, `nw_c2_default5.nss`, `nw_c2_defaultb.nss` (LootingSystemEnhanced/source) — это одни из самых часто кастомизируемых скриптов ИИ существ в модулях NWN. Поскольку override-каталог — плоское пространство имён (один resref = один файл), **любой другой мод/модуль, который тоже переопределяет эти же скрипты, полностью «выигрывает» или полностью «проигрывает»** — конфликт решается не слиянием, а победой последнего загруженного файла целиком.

`default.ncs` — та же история, но уже осознанно задокументирована в `AGENTS.md` как «только MEBOOTSTRAPPER может его предоставлять»; тем не менее это всё ещё жёсткая точка конфликта с любым сторонним (не-Memoria) паком, который тоже кладёт свой `default.ncs`.

### 6. Кастомный TLK-офсет в LSE (Ravick-система локализации)

`RAV_GetStringByStrRef` в `rav_util.nss:130-133` читает `GetStringByStrRef(RAV_STRREF_BASE + RAV_STRREF_OFFSET + nStrRef)`, где `RAV_STRREF_OFFSET = 0` — то есть «сырые» номера строк кастомного `custom.tlk` модуля используются напрямую. Если модуль или другой мод тоже пишет в `custom.tlk` и их диапазоны индексов пересекаются с числами, которые использует LSE (`nStrRef` из `melse_text_*` — там задействован диапазон 1-999), возможна путаница/подмена строк.
